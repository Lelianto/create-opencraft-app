## Version policy — deterministic on purpose

Every dependency in `package.json` is pinned to an **exact version** (`"next": "16.3.0"`,
not `^16.3.0` or `"latest"`). This is deliberate:

- Every project created from this template gets byte-identical, tested dependency versions —
  the starter is deterministic, so "works here" means "works everywhere".
- You do **not** automatically track the latest releases. New dependency versions arrive through
  OpenCraft releases, where they are verified before being pinned.
- A `{{runCommand}} install` will **never** silently upgrade a pinned package.

When you need something newer, upgrade it explicitly (or wait for an OpenCraft update). If a major
version change ever lands, you will see it as a deliberate, reviewed change — not a surprise in CI.

into `.claude/skills`, `.cursor/skills`, `.codex/skills`, `.github/skills`, and `.agents/skills`

## Extending the project

The starter is intentionally minimal: a landing page, a functional app shell, and a set of
installed modules. Capabilities are added through the OpenCraft CLI, which installs versioned,
checksum-tracked modules instead of hand-rolled boilerplate:

```bash
npx opencraft list              # what modules are available and installed
npx opencraft add <module>      # add a module (e.g. dashboard, crud-example)
npx opencraft doctor            # diagnose config, missing files, and env vars
npx opencraft diff <module>     # see how your edits differ from the registry
npx opencraft update <module>   # re-apply an unmodified module's registry files
npx opencraft remove <module>   # remove a module's unmodified files
```

### Presets

Instead of hand-picking modules, start from a validated product preset:

```bash
npx create-opencraft-app my-app --preset saas
npx create-opencraft-app --preset list
```

Presets are validated combinations (architecture + backend + auth + storage + modules) that are
built and tested in CI, so a preset project is deployable from the first run.

### Authentication

If an auth provider is installed, this project ships a working sign-in loop:

- `/auth/signin` — renders the provider's `GoogleSignIn` button and redirects authenticated
  visitors into the app.
- `/auth/callback` (Supabase) or `/api/auth/session` (Firebase) — server-side session exchange.
- A `SignOutButton` component for ending the session.

Authentication is always verified **server-side** via `requireUser()` / `getCurrentUser()` from
`@/infrastructure/auth`. Never trust a client store, header, or query parameter for identity.

## Project layout

- `src/app` — App Router pages and route handlers.
- `src/components/ui` — shadcn/ui primitives. Do not move them.
- `src/features/<feature>` — domain-specific code (feature/hybrid architectures).
- `src/lib` — shared, domain-agnostic helpers.
- `src/infrastructure` — provider SDK setup (auth, storage, database).
- `proxy.ts` — Next.js 16 proxy that refreshes sessions and redirects anonymous visitors.
- `opencraft.config.json` — the machine-readable project configuration OpenCraft reads and writes.
